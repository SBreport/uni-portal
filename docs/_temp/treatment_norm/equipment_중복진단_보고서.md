### 중복 패턴 분석

**주요 패턴 A: 세부 시술명 행 + 통합 마스터명 행 공존 (전체 중복의 약 75%)**

동기화 시 시트에 세부 시술명("리쥬란 힐러", "리쥬란HB")이 이미 있는 상태에서
device_info 매핑 과정에서 상위 마스터명("리쥬란")이 별도 row로 추가됨.
이 패턴은 의도적 분리일 수 있음 — 지점별로 세부 시술을 구분해 관리.

**주요 패턴 B: 같은 장비의 다른 모드/용도 (전체 중복의 약 20%)**

"온다리프팅(얼굴)"과 "온다(바디)", "포텐자", "버츄RF" 등 동일 장비의
적용 부위/모드가 다른 row.

**주요 패턴 C: 수동 마이그레이션 row + sheets row 공존 (소수)**

002 마이그레이션으로 manual INSERT 후 sheets sync가 중복 추가.
광교점 비타민/크라이오가 대표 사례 (003으로 이미 해결).

## B-3. source='manual' (마이그레이션 수동 INSERT)

총 **6건** (광교점 비타민/크라이오는 003 마이그레이션으로 삭제 완료).

| eq.id | 지점 | 이름 | device_info_id |
|-------|------|------|---------------|
| 2387 | 목포점 | 실루엣소프트 | 72 (실리프팅) |
| 2388 | 목포점 | 민트실 | 72 (실리프팅) |
| 2389 | 목포점 | 실루엣픽스실 | 72 (실리프팅) |
| 2390 | 목포점 | 옥토실 | 72 (실리프팅) |
| 2391 | 목포점 | 엠보스몰드실 | 72 (실리프팅) |
| 2392 | 목포점 | 모노실 | 72 (실리프팅) |

**분석**: 002 마이그레이션에서 목포 eq.id=685 "실리프팅" 1건을 6종으로 분리한 row들.
이 6건도 시트 sync가 완료되면 동일하게 sheets row와 중복될 수 있음.

**권장 조치**: 목포점 시트에 이 6개 시술이 실제로 등록돼 있는지 확인.
- 시트에 있다면: 광교점과 동일하게 "시트가 권위" 룰 적용 → 004 마이그레이션으로 manual 6건 삭제
- 시트에 없다면: manual row 유지 (정상)

## 권장 조치 (어드민 도구 신설 우선순위)

### 현황 평가

| 항목 | 수량 | 수동 SQL 처리 예상 시간 |
|------|------|----------------------|
| 566개 중복 그룹 | 1,238 row 영향 | 지점별 확인 포함 약 40~80시간 |
| 여의도 미연결 1건 | - | 10분 |
| 목포 manual 6건 확인 | - | 1시간 |

### 중복 통합 도구가 있다면

어드민 UI에서 "같은 마스터를 가리키는 중복 row 목록 → 통합 또는 분리 확정 → 1클릭 처리"가 가능하면:

- **예상 처리 시간**: 566그룹 × 2분 = 약 19시간 (vs SQL 직접 40~80시간)
- **절감 효과**: 50~75%
- **오류 위험**: SQL 직접 작성 대비 크게 낮아짐

### 우선순위 Top 5 (중복 그룹이 많은 지점)

1. **수원점** (27그룹 61row) — 리쥬란/쥬베룩/보톡스 등 스킨부스터 계열 집중
2. **부산점** (24그룹 52row)
3. **목포점** (21그룹 47row) — manual row 6건 추가 처리 필요
4. **구로점** (19그룹 48row) — 밀크필/버츄RF 계열 4~5건씩 고중복
5. **광교점** (19그룹 43row) — 리쥬란 4건 포함

### 도구 설계 권고

1. **중복 그룹 뷰**: 지점 선택 → 같은 device_info_id인 row 목록 표시
2. **통합 액션**: 선택한 row들 중 1건을 "대표"로 지정 → 나머지 DELETE (이벤트 연결 확인 후)
3. **유지 확정 액션**: "이 그룹은 의도적 분리"로 마킹 → 이후 진단에서 제외
4. **전제 조건 체크**: 삭제 대상 row에 연결된 이벤트/이미지가 있으면 경고
