# 블로그 분석 공통 기준

이 문서는 유니포털 블로그 분석 프로젝트에서 반복적으로 참고할 공통 기준이다.

## 1. 분석 대상 확정 순서

1. 분석 목적을 먼저 정한다.
   - 예: 최적블로그 성과 진단, 브랜드블로그 성과 진단, 계정 건강도 진단, 지점별 실패 원인 분석
2. 분석 기간을 정한다.
   - 월 기준은 기본적으로 `published_at` 발행일을 사용한다.
3. 포함할 원고 유형을 정한다.
4. 제외할 원고 유형을 정한다.
5. 데이터 오류로 보정 포함/보정 제외할 예외를 따로 기록한다.

## 2. 최적블로그 분석 대상 기준

최적블로그 분석에서는 다음 원고를 포함한다.

- `유앤 최적`
- `유앤최적`
- `로컬최적배포`
- `로컬최적`
- `최적블로그`
- 콘텐츠번호 또는 발행명에서 최적 발행 근거가 명확한 원고

다음 원고는 최적블로그 분석에서 제외한다.

- `준최`
- `NB`
- 명백한 브랜드블로그, 카페, 일반 정보성, 임상글, 논문글
- 최적 슬롯명이 없고 원고 유형도 최적이 아닌 원고

단, 담당자 분류 오류로 원고 유형이 잘못 들어간 경우는 예외로 보정할 수 있다. 이때 반드시 프로젝트별 감사 문서에 남긴다.

## 3. 순위 기준

최적블로그 성과 진단에서 기본 판단 기준은 상위10 진입 여부다.

- 성공: 순위 `1~10`
- 실패: 상위10 미진입 전체
- 미노출: 순위 `0` 또는 빈값
- 상위10밖: 순위 `11` 이상

따라서 실패수는 다음과 같이 계산한다.

```text
실패수 = 미노출 + 상위10밖
실패율 = 실패수 / 발행건
```

## 4. 기본 표시 지표

문제 진단 리포트의 기본 컬럼은 다음 순서로 둔다.

- 발행건
- 실패수
- 실패율
- 미노출
- 상위10밖

성공수와 성공률은 실패율과 보완 관계이므로 기본 화면에서는 생략한다. 성공률이 필요한 경우에만 보조 분석으로 추가한다.

## 5. 그룹/계정/지점 분리

분석은 최소한 다음 단위로 나눠 본다.

- 기간 전체
- 월별
- 운영 그룹별
- 블로그 계정별
- 지점/병원별

유앤과 로컬처럼 운영 구조가 다른 그룹은 한 표에 섞어 보지 않고, 공통 요약과 개별 상세를 분리한다.

## 6. 유앤 지점 정규화 기준

유앤 지점은 `evt_branches` 마스터를 기준으로 한다.

2026년 6월 기준 활성 마스터 지점은 43개다.

발행명 정규화 예시는 다음과 같다.

- `유앤강남 최적1` -> `강남`
- `유앤미금 최적1` -> `분당미금`
- `유앤검단 최적1` -> `인천검단`
- `유앤배곧 최적1` -> `시흥배곧`
- `유앤홍대 최적1` -> `홍대신촌`
- `유앤찬동 최적1` -> `창동`

`프로젝트지점`이 비어 있는 유앤 원고가 많을 수 있으므로, 유앤 지점 분석에서는 `발행지점`을 우선 파싱한다.

## 7. 로컬 지점 정규화 기준

로컬 지점은 병원명 또는 발행명을 기준으로 정규화한다.

예시는 다음과 같다.

- `맑은양평 최적배포 5` -> `맑은양평`
- `클리어서울안과 최적배포` -> `클리어서울안과`
- `헤리티지 최적배포 6` -> `헤리티지`

## 8. 위험 신호 기준

기본 위험 기준은 다음과 같다.

- 위험: 발행 5건 이상이고 실패율 70% 이상
- 주의: 발행 5건 이상이고 실패율 50% 이상
- 관찰: 발행 5건 이상이고 실패율 35% 이상
- 급상승: 전월 대비 실패율 25%p 이상 상승

발행건이 적은 계정/지점은 단정하지 않고 관찰 대상으로만 본다.

## 9. 프로젝트별로 반드시 남길 것

각 분석 프로젝트는 다음 문서를 남긴다.

- 기획서
- 분석 대상 감사 문서
- 최종 HTML 리포트
- 상세 CSV 또는 원천 추출본
- 기준과 다른 예외 처리 내역
